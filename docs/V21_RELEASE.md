# v2.1.0 升级说明

> 发布日期：2026-11-27
> 上一版本：v2.0.0
> 定位：补齐路线图剩余项（U4 / E7 / L1 / L3 / L4 / L5 / L6），不改动单文件部署方式，旧接口与返回字段保持兼容。

本项目完全自研，非方糖 / Server酱 的分支或二次开发；`/<key>.send` 仅为本服务主动提供的兼容接入端点。

---

## 一、本次新增能力

### U4｜代码块与示例体验

- 接入示例新增轻量语法高亮：关键字、字符串、注释、数字四类着色，纯字符扫描实现，**不引任何依赖、不访问外部资源**，输出前统一 HTML 转义。
- 代码框增加行号列，超过 14 行自动折叠，提供「展开全部 / 收起代码」入口。
- 示例中的密钥展示为 `x********x`，复制按钮写入 `dataset.full` 中的完整值——展示脱敏、复制可用。
- 长代码在移动端保持横向可滚动，行号列不参与选择。

### E7｜登录页品牌化

- 登录页沿用主界面 CSS，增加品牌标识、版本号、项目简介、首页与 API 文档入口。
- 错误提示从按钮下方移到输入框正下方，失败原因更直观。
- 未配置 `READ_TOKEN` 时由服务端注入温和提示：「当前为公开模式，建议设置查看密钥」。
- 登录页同样支持中英文切换，字典与主界面共用。

### L1｜消息导出

- 服务端：`GET /api/export?format=json|csv|md&limit=1..1000`，按查看权限，返回 `Content-Disposition: attachment`。
- 面板：最近通知区新增「导出 JSON / CSV / MD」三个按钮，按**当前搜索和来源过滤结果**导出，不额外消耗 KV 读。
- 字段包含 `id / title / content / type / source / timestamp / ISO 时间 / 逐渠道投递状态`。
- CSV 带 UTF-8 BOM（Excel 中文不乱码），双引号正确转义，并对 `= + - @` 开头的单元格加前缀，防止 CSV 公式注入。

### L3｜多语言

- 内置中英字典，覆盖导航、区块标题、说明文字、按钮、搜索框、统计卡片、登录页与提示文案。
- 顶部「EN / 中文」按钮切换，选择写入 `localStorage.cfn_lang`，下次打开保持。
- 字典键由测试保证中英完全一致；缺失键回退中文，不会出现原始 key。

### L4｜消息统计看板

- 服务端：`GET /api/stats`，一次列表 + 最多 500 次读取，按需调用，不进入轮询链路。
- 面板新增「统计看板」区块：累计消息、今日消息、来源数、活跃渠道数四张卡片；近 14 天柱状趋势；来源分布；各渠道成功率和投递条数。
- 时间统一按 UTC+8 归集；超过 500 条时明确标注「仅最近 500 条」，避免把采样误读为全量。

### L5｜开放 API 文档

- `GET /docs`：服务端内嵌文档页，沿用主界面样式，列出鉴权方式、全部端点、方法与主要参数。
- `GET /openapi.json`：OpenAPI 3.0.3 机器可读描述，版本随 `VERSION` 自动同步。
- 两页公开可访问，且不含任何密钥、Webhook 或租户配置。

### L6｜多租户准备

- **租户注册表**存账号级 KV（`meta:tenants`），由管理主密钥 `SEND_TOKEN` 通过 `/api/tenants` 增删改查；响应中密钥一律不回显。
- **数据隔离**：租户作用域的 KV 全部加 `t:<id>:` 前缀，消息、渠道配置、模板、设置、投递日志、审计、幂等记录互不可见。
- **密钥隔离**：租户自带 `sendKey` / `readToken`，进入请求作用域后替换 `SEND_TOKEN` / `READ_TOKEN`，管理主密钥不能直接发到租户。
- **配额管理**：`dailyQuota` 按 UTC+8 自然日计数，KV key 设 48 小时 TTL 自动过期；超限返回 429；幂等重放不重复扣减。
- **生命周期**：支持 `enabled` / `status` 停用与重新启用；注销租户只删注册表，历史数据保留，重建后可继续读取。
- **调用方式**：请求头 `X-Tenant-ID: acme` 或查询参数 `?tenant=acme`；不传即默认租户，行为与 v2.0 完全一致。
- **租户自查**：`GET /api/tenant` 返回租户公开信息与当日用量。

## 二、新增端点

| PUT / DELETE | `/api/tenants/{id}` | 管理主密钥 | 更新 / 注销租户 |

## 三、安全与逻辑修正

- CSV 公式注入防护（服务端与客户端两处）。
- 高亮器对全部文本做 HTML 转义，示例代码不再以原始 HTML 注入。
- 租户 ID 白名单校验（2～32 位小写字母、数字、下划线、短横线），拒绝路径穿越式键名。
- 租户作用域 `list()` 返回时剥离内部前缀，避免删除/读取时二次加前缀导致数据错乱。
- 配额计数在幂等命中之后执行，避免上游重试重复扣减。
- 租户未启用 / 状态非 active / 未知租户分别返回 403 / 403 / 404，不泄露注册表内容。

## 四、测试与验证

共 16 套测试脚本全部通过：

- `_test_v21.mjs`：51 项，覆盖文档页、三种导出、统计聚合、租户隔离/密钥/配额/停用、登录页与国际化注入。
- `_test_ui_v21.mjs`：28 项，在真实 DOM 中验证字典键一致性、语言切换、高亮转义、密钥脱敏复制、导出 Blob 与统计渲染。
- 既有 14 套回归测试全部通过，包括渲染语法、真实 DOM、投递、RouterHook、Turnstile、变量模板与 v2.0 专项。

过程中发现并修复的真实问题：

1. 测试仍断言 `textContent` 写入示例，与 v2.1 高亮方案冲突 → 改为校验 `dataset.full` 与高亮转义路径。
2. 多个测试版本号仍写死 `2.0.0`，且 `src/index.js` 版本未同步 → 统一升至 `2.1.0`。
3. CSV 的 BOM 用 `Response.text()` 读取会被 TextDecoder 吞掉 → 测试改为校验原始字节 `EF BB BF`。
4. 直接带查看密钥访问 `/` 会 302 换发 Cookie，测试需先取 `Set-Cookie` 再访问 → 修正会话路径。
5. 发现 CSV 公式注入风险 → 服务端与客户端同步加防护并补测试。
6. jsdom 测试进程因定时器不退出 → 末尾显式 `dom.window.close()`。

## 五、兼容与升级

- KV 绑定 `NOTIFICATIONS`、Durable Object `ROUTERHOOK_SENSOR` 不变，旧数据可直接读取。
- 未调用租户接口、不带 `X-Tenant-ID` 时，所有行为与 v2.0 一致；不需要新增环境变量。
- 租户密钥目前以明文存入自有 KV（与环境变量中的密钥同级），请勿把 KV 内容公开分享；如需更高安全等级，可后续改为哈希存储 + 一次性展示。
- 多租户是「架构建模准备」，**不等于托管 SaaS 已完成**：计费、支付、服务条款、 abuse 防护仍需单独实现。

## 六、部署

单文件部署方式不变。首次部署可直接上传 `worker.js`；升级部署须保留原有 `NOTIFICATIONS` 与 `ROUTERHOOK_SENSOR` 绑定。旧消息、渠道配置、模板、密钥轮换状态均保留。
